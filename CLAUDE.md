# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

ERGMUserterms.jl is a Julia port of the R `ergm.userterms` package (StatNet collection) that provides templates, utilities, and validation tools for developing custom ERGM (Exponential Random Graph Model) terms. It integrates with ERGM.jl and Networks.jl for model estimation.

## Development Commands

- **Run tests:** `julia --project -e 'using Pkg; Pkg.test()'`
- **Load package in REPL:** `julia --project -e 'using ERGMUserterms'`
- **Build docs (strict):** `julia --project=docs -e 'using Pkg; Pkg.instantiate()'`, then `julia --project=docs docs/make.jl` — `warnonly=false`, `checkdocs=:exports`: an undocumented export, a bad cross-reference or a malformed docstring is a build error.
- **Execute every README/docs code block** (the site repo's checker; needs the `../.snippet-env` from `tools/README.md`): `SNWJ_ROOT=<monorepo root> julia --project=../.snippet-env ../statistical-network-analysis-with-Julia.github.io/tools/check_snippets.jl ERGMUserterms.jl` — required 7/7 PASS with no ERGMUserterms warning in the output. The test suite runs the CI-runnable equivalent (see Architecture).
- **Allocation gates / benchmarks:** `julia --project=benchmark -e 'using Pkg; Pkg.instantiate()'`, then `julia --project=benchmark benchmark/regression_tests.jl` (the pins CI runs) and `julia --project=benchmark benchmark/benchmarks.jl` (BenchmarkTools `SUITE`, `BENCHJL` rows, scaling assertion). `benchmark/Project.toml` sources the siblings as `../../ERGM.jl` / `../../Networks.jl` (two levels up — the off-by-one of panel item 7).
- **Template package tests:** `julia --project=examples/MyTermPackage -e 'using Pkg; Pkg.instantiate(); Pkg.test()'` (also a CI step).
- **Regenerate the R fixture:** `Rscript test/fixtures/r/userterms_examples.R > test/fixtures/userterms_examples.toml`

## Architecture

The package is a single-module design in `src/ERGMUserterms.jl` with no sub-files. It contains:

- **Abstract type:** `AbstractUserTerm <: AbstractERGMTerm` -- base type for all user-defined terms.
- **Term interface:** Every term must implement three methods: `name(term) -> String`, `compute(term, net) -> Float64` (full network statistic), and `change_stat(term, net, i, j) -> Float64` — the **add-direction** change statistic `g(y⁺ij) − g(y⁻ij)` (statistic with edge (i,j) present minus absent), independent of the dyad's current state. The toggle-direction idiom `has_edge ? -Δ : Δ` is wrong and is rejected by the harness. The interface generics live in ERGM.jl; this package does `import ERGM: compute, change_stat, name` and re-exports them so user methods extend the right functions.
- **Term traits (the second half of the contract):** ERGM.jl's public term-trait protocol (`ERGM.jl/src/terms/traits.jl`) is how a term declares what it needs; ERGM's *formula validation and materialization read the traits, not term types*, so a user term is validated exactly like a built-in (this was ERGMUserterms.jl#1 — before it, only ERGM's own attribute terms were validated and user terms silently passed through). Declare what is not at its default: `ERGM.required_vertex_attributes(t) = (t.attr,)` and `ERGM.required_edge_attributes` (default `()`; declare an attribute **iff its absence is an error** — `WeightedEdges` reads `:weight` but defaults it, so it declares nothing, while `InteractionTerm` declares both of its attributes because without them it collapses to a constant zero); `ERGM.requires_directed`/`requires_undirected` (default `false`); `ERGM.is_dyad_dependent` (fallback `true`; subtyping ERGM's `NodalTerm`/`DyadicTerm` implies `false`); `Networks.supports_missing` (default `false`; `true` only if the statistic consults `is_missing_dyad` and so ignores masked dyads' face values).
- **`@ergm_term` macro:** After evaluating the body, checks that the type subtypes AbstractERGMTerm and has non-fallback compute/change_stat/name methods, warning on gaps (`_check_term_definition`). Its docstring example is a real term (`ScaledEdges`) whose `compute`/`change_stat` return numbers and which `validate_term` accepts.
- **`src`/`dst` are Graphs.jl's.** `edges(net)` is re-exported by Networks.jl but `Graphs.src`/`Graphs.dst` are not (neither by ERGM.jl), so every term that iterates edges — and every doc/README example that does — needs `using Graphs: src, dst`; a missing import is an `UndefVarError` inside `compute`, which `validate_term` reports as `compute() failed` and which the docs-execution gate turns into a test failure. The package itself does `using Graphs`.
- **One import idiom in every entry page.** README, `docs/src/index.md`, `getting_started.md` and the guides all teach `import ERGM: name, compute, change_stat`; `import ERGMUserterms: …` is the same three functions (pinned by "Shared verbs are the shared generics") and the prose says so once. A bare `using` followed by `name(::MyTerm) = …` defines a *local* function ERGM.jl never calls — the silent failure that broke the pre-WP3 `index.md` Quick Start (it "ran" and `validate_term` warned `compute() not implemented`).
- **Validation/testing:** `validate_term()`, `validate_traits()`, `change_stat_check()`, `consistency_check()`, `test_term()` -- verify the add-direction invariant by brute-force toggling AND check state-independence. **Unfittable networks are refused up front, never given a verdict:** every entry point that takes a network (`validate_term`, `validate_traits`, `change_stat_check`, `consistency_check`, `benchmark_term`) calls `_refuse_unfittable(net, entry)` first, which throws an `ArgumentError` on (a) fewer than 2 vertices — no dyad to check (the validators used to `return true`); (b) a two-mode network — the dyad draws/enumerations range over every off-diagonal pair, and on a two-mode network the within-mode pairs cannot hold an edge (`add_edge!` returns `false`), so the brute-force reference would read 0 there and report a correct term inconsistent (round-1 finding); (c) a self-loop present (ERGM models the off-diagonal dyads only; round-2 finding: such a network was validated with `compute` counting the loop and then rejected at step 5 in words blaming the term). Cases (b) and (c) call ERGM's `public` `_refuse_two_mode` / `_refuse_self_loops` — the very functions `ERGMModel` runs — and prefix their `ArgumentError` with the entry point (`"validate_term validates terms on networks ERGMModel accepts only, and ERGMModel refuses this one: …"`), so the wording is ERGM's and cannot drift (the reconciliation round replaced the hand-mirrored copies; the testset checks the message ends with ERGM's own). **No verdict without evidence:** `_require_positive` enforces `n_tests >= 1` (`validate_term`, `change_stat_check`, `test_term`) and `n_iter >= 1` (`benchmark_term`); `test_term` refuses `n_vertices < 2`, and `_random_network` refuses a `density` outside `[0, 1]` (so `profile_term` does too). A testset enumerates keyword combinations and asserts `ToggleConventionTerm` cannot pass any of them. **A ✓ line is printed only for a check that ran:** an attribute that is constant on the network cannot be perturbed, so `_reads_attribute` returns `missing` and `validate_traits` warns `… is constant on this network, so whether the term reads it is undecidable` — a failure for a *declared* attribute (the network is not one the term is meant for), a warning for an undeclared one — and replaces the `✓ declared attributes match …` line with one naming what could not be tested; the dyad-independence check likewise says so when there is no other dyad to toggle. **The bare-`using` hint:** `_only_fallback(f, Tuple{T, …})` decides whether any `compute`/`change_stat`/`name` method for `T` reaches the shared generic; when none does, `validate_term`'s failure lines and `_check_term_definition` append `_no_method_hint` (`… reaches the shared generic; if you defined one after a bare \`using\`, it is a local function ERGM.jl never calls: add \`import ERGM: name, compute, change_stat\` …`), pinned by a testset that defines a term in a fresh module without the import. **Masked dyads are face value** for a term with `supports_missing == false`: `_masked_face_value_notice` logs one `@info` (`net has k masked dyads; … validated at their face value`) from `validate_term`, `change_stat_check` and `consistency_check` when verbose — the missing-data contract's "say so" — and the verdict is unchanged. The harness snapshots/restores the dyad's edge attributes across toggles (rem_edge! deletes them), treating them as exogenous dyadic data, through the public attribute API (`set_edge_attribute!(…; require_edge=false)` restores a value on a removed dyad — no reach into `net.edge_attrs`). A declared vertex attribute must have a value on **every** vertex: `validate_traits` reports the vertices without one, and step 5 (`ERGMModel` construction, i.e. `ERGM._validate_formula`) refuses the term with ERGM's own message, because statnet refuses NA — the `get(attrs, v, 0.0)` zero-fills in `InteractionTerm`/the test terms are unreachable through a model for a declared attribute. `validate_traits()` (run by `validate_term` unless `traits=false`) tests the *declarations*: it perturbs each attribute (rotate values, then collapse them — rotation alone misses partition-only terms like nodematch) to check that the declared attributes are the ones the term reads (an undeclared **vertex** attribute read is a failure — that is the silent-all-zero-column trap; an undeclared **edge** attribute read is only a warning, since defaulting terms are legitimate); builds the direction twin of the network to check a `requires_directed`/`requires_undirected` declaration is enforced by `ERGMModel`; toggles *every other dyad* (not a random sample — a violation may hide in the reverse arc alone) to check an `is_dyad_dependent = false` claim; flips the face value of masked dyads to check a `supports_missing = true` claim; and finally requires `ERGMModel` construction to accept the term.
- **Package template:** `examples/MyTermPackage/` — a copyable skeleton (Project.toml + src + test) of a third-party term package: `ReciprocatedHomophily` declares all four traits, passes `validate_term`, and fits inside an `ERGMModel`. Its module is `include`d by this package's own test suite, so the template cannot rot. Every `fit_ergm` call in it (test, README, docstring) passes `rng=Xoshiro(1)` — the template models the rng contract end to end — and its `_counts` reads the attribute per vertex (`get_vertex_attribute(net, attr, v)`), so the copied term is allocation-free.
- **Randomness (panel 2026-09, item 6):** every harness entry point — `validate_term`, `validate_traits`, `change_stat_check`, `consistency_check`, `test_term`, `benchmark_term`, `profile_term` — takes `rng::AbstractRNG=Random.default_rng()` and draws **all** of its randomness from it (`_random_dyad(rng, n)`, `_other_dyads(rng, …)` with `randperm(rng, …)`, `_random_network(rng, …; directed)`); there is no bare `rand`, no rng-less `randperm` and no `Random.seed!` anywhere in `src/` (a testset greps for them). Two calls with equal rngs visit the same dyads and return the same verdict at any thread count, and the caller's rng is advanced (draws come from it, not a copy). The default is the task-local RNG, so `Random.seed!` still governs an unseeded call; an explicit `rng=Xoshiro(seed)` is the way to make a call independent of global state. Each entry point builds a `_HarnessContext(entry, rng)` on entry that snapshots the rng state as a literal `Xoshiro(0x…, 0x…, 0x…, 0x…)` (`TaskLocalRNG` copies to a `Xoshiro`; other rng types give `nothing`); `_replay_hint(ctx)` appends `; reproduce with rng=<literal> passed to <entry>` to **every** failure `@warn` (`_dyad_consistent` takes the context as an argument — never a global), and `test_term` prints the literal in its header. Because the harness draws straight from `rng`, passing the literal back replays the identical dyad sequence — that is why the state is snapshotted rather than a seed drawn (a drawn seed cannot be handed back as `rng=`). `validate_term` and `test_term` honour `n_tests` (at least 1, capped at the number of dyads; `validate_term` forwards `min(n_tests, n_dyads)` to `change_stat_check`). `test_term` **and `profile_term`** take `directed=true` and `vertex_attributes=Dict{Symbol,Any}()` (`attr => v -> value` or `attr => vector`, applied by `_apply_vertex_attributes!` to every generated network — `test_term`'s random, empty and complete ones alike): without them they can only exercise a bare directed network, and the template's `ReciprocatedHomophily` (declares `:group`) or any `requires_undirected` term "fails" the tutorial's step 3 (round-1 finding) or cannot be profiled at all (round-2 finding); testsets run both green and a `ProbeTerm` asserts every generated network has the requested kind. `consistency_check` enumerates each **unordered** dyad once on an undirected network (`i < j`, the `_term_fingerprint` rule; random draws canonicalised to `minmax`, budget `min(100, _n_dyads(net))`).
- **Benchmarking:** `benchmark_term()` *times* `compute()` vs `change_stat()` (`n_iter` calls each; it is not a profiler); `profile_term()` runs it across sizes, building networks exactly as `test_term` does (`directed=`, `vertex_attributes=`). Both draw their dyads/networks from `rng`. `benchmark_term` refuses `n_iter < 1` and, through `_refuse_unfittable`, `nv < 2`, two-mode and self-loop networks with an `ArgumentError`.
- **Example terms:** `ExampleTerm`, `TemplateTerm`, `WeightedEdges`, `DyadCovTerm`, `InteractionTerm` -- shipped as reference implementations, each pinned against its statnet twin (see Validation against R).
- **Doc helpers:** `term_signature()`, `term_documentation()` for auto-generating term docs.
- **Documentation gates (grade-A criterion 5), both in `test/runtests.jl`:**
  - *"Every exported docstring carries a runnable example"* walks `names(ERGMUserterms)` and requires an ERGMUserterms-owned docstring with at least one ```` ```julia ```` block for every export — including the docstrings this package attaches to the re-exported generics `name`/`compute`/`change_stat` — and evaluates every block in a fresh module that has only done `using ERGMUserterms` (so an example that needs `Networks`, `Random` or `Graphs: src, dst` says so itself), under a `NullLogger`; `@test length(blocks) >= 18` (19 at the time of writing). Sketches that are deliberately not standalone use a ```` ```jl ```` fence.
  - *"README and docs pages execute without warnings"* is the CI-runnable form of the site's `check_snippets.jl` (which needs an environment CI cannot build): it extracts the ```` ```julia ```` blocks of `README.md` and every `docs/src/**/*.md` with the checker's skip rules (```` ```julia-repl ````, `<!-- skip-check -->` on the line above, `Pkg.` blocks, output-only blocks under an `Output:` label, unparseable blocks), runs each file's blocks sequentially in one fresh module with `REPL.softscope` inside a temp dir with stdout redirected, and fails on any exception **and on any `@warn` record whose `_module === ERGMUserterms`** — every validator warns on every failure, so an example that "runs" while `validate_term` returns `false` now fails the suite instead of printing a warning nobody reads. Every page claim that used to be a bare call (`valid = validate_term(…)`) is followed by `@assert valid` for the same reason. It also greps every doc line for `using .*\bNetwork\b` (the pre-rename module name; panel item 2). **Output comments are gated too** (round-2 finding: pages quoted `30.0`/`4.0`/`12.0`/`4200.0` for runs that produce 26.0/3.0/6.0/990.0): the page's stdout is captured to a temp file and its `@info` records collected, and every numeric `compute() returns: X` / `Works on empty|complete network: X` comment on the page must be a value some run on that page produced (`claim_re`; a `…` placeholder is not a claim). `@test n_claims[] >= 6`.

## Validation against R

- `test/fixtures/userterms_examples.toml` (script `test/fixtures/r/userterms_examples.R`; ergm 4.12.0 / R 4.6.1; `[provenance]` block, loaded with `Networks.load_golden`, which throws without one) pins **every bundled term and the harness's brute-force reference** against the statnet terms they are identical to: `ExampleTerm` = `nodecov("id")` (id = vertex index), `TemplateTerm(1.0)` = `edges`, `WeightedEdges()` = `edgecov(W)` (2.5 on the weighted arcs, 1.0 = the default elsewhere), `DyadCovTerm(cov)` = `edgecov(cov)` with asymmetric `cov[i,j] = 2i + j`, `InteractionTerm(:a,:b)` = `edgecov(M)` with `M = a bᵀ + b aᵀ`, and the template's `ReciprocatedHomophily(:group)` = `mutual(same="group", diff=FALSE)`. Recorded: `summary()` and the full `ergmMPLE(output="array")` change-statistic array (row-major over ordered dyads i ≠ j, 56 values per term) on an 8-vertex directed network built from a literal edge list (the template's test network plus four arcs), and the same for the five bundled terms on its undirected projection (i < j, 28 values; `W`/`cov` symmetrised to their `(min,max)` entry, which is what pins the canonical-key branches). Tolerance `1e-9` everywhere — deterministic integer/rational arithmetic on a fixed graph, no estimator, no Monte Carlo; a disagreement is a term bug, never a reason to loosen.
- The testset "Golden: bundled terms and the harness match statnet" compares `compute`, `change_stat` on every dyad (both dyad orders when undirected) AND `_brute_change_stat` on every dyad — so `validate_term`'s reference is R's number, not a self-consistency check. R's coefficient labels (`nodecov.id`, …) are recorded but asserted NOT to be claimed: user terms keep their own names. `ergm.userterms` itself (a C template, archived from CRAN, not installed) is not a counterpart of anything shipped here and is not used.

## Performance pins

- `benchmark/regression_tests.jl` and the testset "Allocation regressions" pin, for every bundled term AND the template's `ReciprocatedHomophily` (Julia 1.12.6, 2026-09-12): **0 B** per `change_stat` and per `compute` (directed and undirected networks), and `Base.return_types(change_stat, (T, typeof(net), Int, Int)) == [Float64]` (likewise `compute`). The inference pin is the load-bearing one: the attribute stores are untyped (`Dict{Int,Any}` / `Dict{Tuple{Int,Int},Any}`), so a `get(get_vertex_attribute(net, attr), v, 0.0)` read infers `Any` — round 1 shipped `WeightedEdges`/`InteractionTerm` that way (96 B / 208 B per call) and ERGM's `_change_stat_tuple` inferred `Tuple{Float64, Any}` for any model containing them. The terms now read per element with `get_vertex_attribute(net, attr, v)` / `get_edge_attribute(net, attr, i, j)` (0 B; they return `nothing` when absent and canonicalise the undirected key — the whole-Dict getters allocate an empty default `Dict` on every call, a Networks.jl inefficiency recorded as a cross-repo request) and assert `::Float64`. The typed snapshot at construction (`vertex_attribute_vector(net, attr, Float64)`, term_interface.md) is still the recommended hot-path pattern (vector index vs two hash lookups). Any allocation or an `Any` return type is a regression.
- `_term_fingerprint` is exactly one `compute` + one `change_stat` per dyad (O(n²)); `_other_dyads` caps its result at 250 dyads (tested on a 30-vertex network with 870 ordered dyads).
- `benchmark/benchmarks.jl` asserts the per-dyad `change_stat` cost of every bundled term grows by at most 3× from n = 500 to n = 2000 at constant mean degree (O(1)/O(degree), never O(edges)).

## CI

- `.github/workflows/CI.yml` and `Documentation.yml` **derive** the sibling clone list from `[sources]` (`sed -n '/^\[sources\]/,/^\[/p' ERGMUserterms.jl/Project.toml | grep -oE '^[A-Za-z]+'`; the docs workflow reads `docs/Project.toml` and drops the self entry) — never a hand-written list. The testset "CI clone lists are derived from [sources]" runs that pipeline in a scratch copy of the layout and asserts it yields `keys([sources])`, so the two cannot diverge. `--depth 1` of `main` is the pre-release arrangement (release tags replace it at panel item 21). The ubuntu/`1` cell additionally runs the benchmark environment's `regression_tests.jl` and the template package's `Pkg.test()`. No `JULIA_NUM_THREADS` cell: the package spawns no tasks.

## Key Dependencies

- **ERGM.jl** -- provides `AbstractERGMTerm`, core ERGM functionality
- **Networks.jl** -- network data structure (`Network`, `has_edge`, `add_edge!`, `rem_edge!`, `nv`, `ne`, etc.)
- **Graphs.jl** -- graph algorithms and iteration (`edges`, `vertices`, `src`, `dst`, `outneighbors`, `inneighbors`)
- Requires Julia >= 1.12 (Networks.jl cannot load on earlier versions)

## Conventions

- Term structs should be **immutable** (`struct`, not `mutable struct`) and subtype `AbstractUserTerm`.
- `change_stat()` should be O(degree), not O(edges), for performance.
- Term names should be descriptive and include parameters (e.g., `"template.$(t.param)"`).
- Validation uses a tolerance of `1e-10` for floating-point consistency checks.
- Never call bare `rand()`/`randperm(n)`/`Random.seed!` in `src/`: every draw goes through the `rng` keyword (see Randomness above), and the test suite fails on a bare draw.
- Tests use the **public** trait names (`ERGM.requires_directed`, `ERGM.required_vertex_attributes`, `ERGM.has_dyad_dependent`); the one private alias pinned (`ERGM._requires_directed === ERGM.requires_directed`) exists because TERGM.jl still declares methods on it.
- Every export gets a docstring with a runnable ```` ```julia ```` example that does its own `using` and ends in an assertion-style comment (`# true`); every README/docs block either runs as written (with `@assert` on its claims and an explicit `rng=Xoshiro(…)`) or is marked `<!-- skip-check -->` on the line above. Both are enforced by the testsets above.
- **Not ported from R `ergm.userterms`** (documented in README, `docs/src/index.md` and the CHANGELOG): the C `changestats.users` template and the `mindegree` example term. The Julia counterpart of the C template is `examples/MyTermPackage/`. The migration story (README "Term Interface", term_interface.md "Common bug", CHANGELOG Breaking) says that the rejected toggle-direction idiom is R ergm's own C `edgestate` convention (`CHANGE_STAT[0] += edgestate ? -1 : 1`): a ported changestat drops the `edgestate` sign.
- All exported symbols are declared at the top of the module; there are no separate include files.
